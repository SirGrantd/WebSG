# Operational Guidelines and Agent Protocols

## 1. Development & Code Generation Guidelines
- **Approach Confirmation on Development:** Whenever code development or modification is requested, always ask the user whether they prefer a presentation of code snippet examples first or direct file modifications.
- **AI Attribution and Purpose Comment:** Every code file or snippet generated by AI must contain a header comment explicitly stating that it was generated by AI and describing its objective and purpose.
- **No Line-by-Line Commenting:** Do not add trivial or redundant comments for every single line or small code chunk. Keep code self-documenting and focus comments only on high-level intent.
- **No Over-Abstraction:** Never introduce unnecessary abstractions, wrapper layers, or excessive repetitions. Code should remain direct, lean, and purpose-built unless an abstraction is strictly required or explicitly requested.
- **Think Before Coding:** Present ideas explicitly. Ask before assuming. Challenge when a simpler approach exists.
- **Surgical Changes:** Modify only what is strictly necessary. Do not refactor or "improve" code outside the direct scope of the request. Preserve existing code style and unrelated comments.
- **Read Before Write:** Always inspect directories and existing files before modifying or adding code.
- **Tests Verify Intent:** Tests must verify *why* behavior matters, not just *what* it does. A test that cannot fail when business logic changes is invalid.
- **Step Verification:** Summarize what was done, what was verified, and what remains after each significant step.
- **Expose Failures:** Never silently ignore errors, suppress failures, or skip tests.

## 2. Security & Environment Rules (Highest Priority)
- **Zero Access to Secrets:** NEVER inspect, read, summarize, or display contents of environment variable files (`.env`, `.env.*`) or shell profile files (`.bashrc`, `.zshrc`, `.profile`, etc.). Request any required values directly from the user.
- **Destructive Git Commands:** NEVER execute or suggest destructive Git commands such as `git push --force` or `git reset --hard`.
- **Git & GitHub Operations:** Advisory mode by default. The user performs Git operations manually. Do not run `git commit`, `git push`, or `git merge` unless explicitly commanded.
- **Restricted GitHub MCP:** GitHub MCP usage is strictly consultative and gated. Never invoke it autonomously.

## 3. Architecture, Context & Containers
- **Context & Documentation:** When extensive documentation is requested, store it inside the project's `/.notes/` directory in Markdown (`.md`) format.
- **Docker Containers:** Whenever Docker setup is needed for the project, create all configuration files inside the `.docker-dev-<project_name>` directory (which must be included in `.gitignore`).
- **Operating Environment:** Linux native (EndeavourOS / Arch Linux). POSIX standard paths and Unix `LF` (`\n`) line endings exclusively.
